# 磁盘与缓存生命周期（适用项目必须落实）

适用于产生镜像、构建缓存、临时产物或持续日志的开发管理器。本机和容器模式均按实际资源实现，不为轻量项目引入 Docker、后台服务或复杂评分系统。以下水位和期限是可配置的初始策略；归属、持久数据保护和有界执行是不可放宽的清理边界。

## 空间压力与预算

- 按资源实际所在文件系统计算使用比例，明确容量、调用身份可用空间及计算口径；项目目录、Docker 数据目录、远程 daemon/虚拟磁盘可能不在同一文件系统。相同文件系统去重，不能用客户端根分区代替远端空间。查询失败标记未知，不能当作空间充足或伪造数据。
- 默认按使用率分级：低于 75% 仅回收长期闲置缓存；75%–85% 回收过期且重建便宜的缓存；85%–92% 逐批扩大候选范围；达到 92% 优先回收，仍处于临界状态或预计空间不足时拒绝新的重型构建，保留已有服务。
- 使用滞回避免抖动：初始可设 75% 触发、70% 退出，85% 触发、78% 退出，92% 触发、85% 退出。阈值须有序、退出线低于触发线；高级压力缓解后重新评估当前等级，不能跨等级无限清理。
- 剩余空间判断以比例为主，不硬编码“低于若干 GB”作为通用规则。构建准入同时参考历史峰值新增空间、并发构建预留和安全余量；冷启动没有历史时明确估算与不确定性。容量、配额或 inode 耗尽等实际限制不能被健康百分比掩盖。
- 缓存预算作为兜底，结合磁盘容量比例、项目活跃度和可配置上限制定，不要求所有项目统一固定 GB 数。单项目预算不能保证整机总量：跨项目预算只能由明确配置的整机协调器管理，项目脚本无权据此清理其他项目。

## 闲置过期、分块与重建成本

- 闲置期限从最后一次真实使用计算，不以创建时间替代。优先使用后端可靠的使用记录，必要时记录管理器可观测的命中/使用时间；禁止把 status 扫描当作使用，也不能依赖不可靠的文件 atime。未知使用时间的既有缓存不得直接判为过期，可从首次观察起给予宽限期。
- 初始闲置期限：临时上下文和可重建中间产物 3–7 天，普通构建层和前端缓存 7–14 天，下载包及昂贵依赖编译缓存 14–30 天。项目选择具体期限并展示配置；空间充裕时优先保留昂贵缓存，空间压力上升时可按明确策略缩短期限。
- 先按后端支持的缓存记录/类型分批回收，再考虑整个闲置缓存集合。排序综合闲置时长、近期命中、项目活跃度、实际可释放空间与重建成本，优先处理长期闲置、释放多且重建便宜的对象。成本包括编译耗时、下载量及网络可用性，不仅是文件大小。
- 首版允许按类型估算成本，后续可根据构建耗时和命中记录改进。标明估算来源，不能宣称 Docker 自动提供每层精确重建成本；共享层的逻辑大小不能直接相加为可回收空间。
- 先核对目标版本的工具能力、过滤条件及组合语义。后端不支持细粒度或成本排序时，使用可验证的类型/时间过滤并说明局限，不模拟不存在的能力，不通过手删底层文件实现分块。
- 长期闲置项目可以逐级回收至全部可重建缓存；保护清单、当前运行依赖和用于回退的版本不因 TTL 到期而失效。

## 触发时机与停止条件

- start/build/reload 在实际安装依赖或构建前进行轻量空间检查；按压力和期限触发受控清理。正常空间下保留增量缓存，不在每次构建前无条件 prune 或禁用缓存。
- 成功构建后回收过期临时缓存；部署镜像的版本淘汰须等待更新及健康检查成功。失败时保留上一可用版本、诊断信息和恢复所需资源；可按保留期轮转失败日志。
- 每轮限定时间、批次和删除量，逐批复核实际空间；达到退出线、预算/过期候选已处理完、无可回收候选、无进展或达到执行上限即停止。未达目标时明确报告原因，不能无限重试或扩大到业务数据。
- 清理前获取与构建互斥的资源锁，删除前再次核验身份、引用和活跃使用。共享构建器需要构建器级协调；所有参与者无法协调时跳过不安全对象。不能只靠“未发现 cargo/docker 进程”判断可删。
- 自动维护失败与业务结果分开报告：构建前空间不足阻止构建；成功部署后的清理失败应报告维护告警，不能把健康服务误报为部署失败。
- 可接入已授权的定时维护来覆盖长期不再启动的项目；仅有生命周期 hook 时明确它不会在闲置期间自动运行。更新技能或普通项目实现不意味着授权安装整机定时任务。定时维护无变化时静默，仅空间压力、失败或需要人工处理时通知。

## 清理边界与具体资源

- 每个候选必须能验证 repoKey、管理器标记、实例/环境和确切资源 ID 或受管路径。无标签、未使用、已停止并不等于属于本项目；归属不明或共享资源跳过。既有资源迁移先登记/核验，不能猜测认领。
- 自动清理和普通 clean 均排除源码、未提交修改、配置、凭据、证书私钥、数据库、上传文件、对象存储和业务卷。任何持久数据删除须由独立、明确的数据重置操作处理；磁盘压力、TTL 或 force 参数不能绕过保护。
- 禁止项目清理调用无范围的 docker system/image/builder/volume prune、compose down -v，禁止直接删除或截断 Docker/containerd/BuildKit 存储文件与日志。专属构建器可用其受支持的 scoped prune；共享构建器若无法按归属可靠过滤，则不自动 prune。
- 本机缓存只处理适配器明确登记的可重建目录，核验真实路径和符号链接边界，使用包管理器/构建工具的受支持清理方式。不得按目录名称通配删除所有 target/node_modules/.local 或用户全局缓存；运行服务所依赖的产物不得删除。
- 镜像保留当前部署与至少上一健康版本，并保护所有容器（包括已停止容器）的引用。仅淘汰归属已验证、超过保留策略且无引用的版本。避免每次构建累积永久标签；失败部署不提前淘汰回退版本。
- 同一仓库与兼容构建配置复用稳定构建器身份；资源限制或配置变化需要新构建器时，登记旧实例、占用与退役条件，避免持续累积。旧构建器只在无活动构建且缓存/引用策略允许时退役。
- 持续日志必须有轮转和总量上限，默认可采用每文件 10 MiB、保留 3 个文件；本机进程与容器均覆盖。现有容器未应用新配置时如实展示，不能为让日志配置生效暗中重启整套服务。

## 配置、界面与验收

- 策略集中到现有本地配置 owner（例如 .local/mode.json），包含百分比水位/退出线、期限、预算、保护项及维护执行上限。使用/成本采样、候选清单、清理结果和锁属于运行状态，独立保存并轮转，不复制另一套配置。
- 提供安全清理和纯预览入口，可命名 mode:clean 与 mode:clean --dry-run，也可复用现有等价命令。预览不得删除、更新使用时间或触发后端 GC；展示范围、候选理由、保护/跳过原因、预计回收量及估算限制。实际执行复核候选，不把过期预览当删除授权清单。
- status 保持只读，展示实际文件系统水位、项目缓存/预算、策略与最近清理结果；重型统计应有超时和带时间戳的缓存，不能让每次 status 全盘扫描。help 按控制台契约提供维护分组和实际可用的预览示例。--json 仅显式启用。
- 实现时用隔离夹具验证：阈值边界与滞回、最后使用/未知时间、昂贵缓存后清理、共享层估算、分批停止、无进展退出、归属/符号链接保护、并发构建互斥、只读 dry-run、失败部署回退保护和查询失败。不得为测试填满真实磁盘或删除真实项目数据。只更新技能文档时检查规则与引用一致性，不启动业务服务。
