# 控制台输出：必须实现的用户界面

命令集合可以按项目裁剪，但人类可读格式不能裁剪。本文是实现 status/help 及生命周期输出前必须读取的验收契约，不是可选美化建议。项目名与字段来自实际项目，不依赖任何其他仓库。

## 输出模式必须显式分离

- `mode:status` 默认输出人类状态面板，`mode:help` 默认输出分组帮助；禁止直接打印对象、JSON.stringify(state)、裸字段列表或一整段英文说明。
- 默认 `mode:health` 也输出简洁的健康摘要；自动化使用 `mode:health --json`。status 支持 `--json` 时也必须显式指定才输出 JSON。健康失败仍返回非零退出码，展示格式不影响退出码。
- 非 TTY、管道、NO_COLOR 和 FORCE_COLOR=0 **只关闭 ANSI 颜色**，仍保留标题、分隔线、缩进、对齐和分组；不得自动切换成 JSON，也不得压成一行。
- `--json` 优先于所有颜色配置。管理器 stdout 仅输出一个合法 JSON 值，不能夹带标题、进度、ANSI 或子命令日志；诊断写 stderr。验证 package runner 是否回显命令，必要时用其静默选项或直接调用脚本验证 stdout。
- 中文项目默认中文标签、说明和状态。保留命令名及必要技术名词，内部枚举 `ready`、`selected`、`healthy` 应映射为“运行正常”“当前模式”“健康检查”，不能直接展示内部对象。

## status 的最低布局要求

必须包含：上下分隔线、加粗项目标题、带文字的状态符号、对齐的标签/值、按信息类别留空行、底部下一步命令。优先展示状态和可访问 URL，其次健康/证书，最后目录/标识/日志等诊断信息。字段按项目实际情况裁剪；未知值写“未获取”，不能伪造 PID、运行时间或健康结果。

下面是本机模式布局示例，颜色见后文。单一运行方式无需强加模式选择。

```text
──────────────────────────────────────────────────────────────────────
  示例项目 · 开发环境                            ● 运行正常
──────────────────────────────────────────────────────────────────────
  当前模式  local · 本机开发
  访问地址  https://127.0.0.1:23428
  局域网    https://192.168.182.137:23428
  监听范围  0.0.0.0

  健康检查  ✓ 服务已就绪
  TLS 证书  ⚠ 自签证书 · 浏览器信任未验证

  项目目录  /workspace/example
  仓库标识  a01df4642f22
  证书文件  /workspace/example/.local/mode/cert.pem
──────────────────────────────────────────────────────────────────────
  mode:logs 查看日志 · mode:reload 更新预览 · mode:stop 停止服务
```

容器项目可增加容器/镜像字段；有运行时长、端口顺延、依赖检查或 Git 信息时按组补充。不要为了对齐样例硬编码运行数据。标题右侧状态在窄终端可换到下一行。停止显示“○ 已停止”和启动指引；健康异常显示“⚠ 健康异常”、具体原因和排障命令。停止后不把旧 URL 当作仍可访问的地址。

产生缓存或持续日志的项目，status 还须按 [磁盘与缓存生命周期](storage-lifecycle.md) 展示空间水位、缓存预算与维护结果；查询保持只读，未知值和带时间戳的估算明确标记。help 增加已实现的维护命令与清理预览示例。

## help 的最低布局要求

必须包含标题、用途/调用格式、适用时的当前/默认模式、分组命令表、每条命令的说明和少量可复制示例。命令与说明分成两列对齐，组间空行；禁止仅打印命令数组或把所有语义挤进几个长句。

下面仅演示排版。只展示项目真实实现的命令；不要求增加这些模式和命令。

```text
──────────────────────────────────────────────────────────────────────
  示例项目 · 开发命令
──────────────────────────────────────────────────────────────────────
  用法      bun run mode:<命令> [参数]
  当前模式  local · 本机开发

  服务管理
    mode:start          启动当前开发环境
    mode:stop           停止服务，保留数据
    mode:reload         应用最新代码并准备预览
    mode:restart        重启现有服务，不重新构建

  状态与排障
    mode:status         查看当前环境和访问地址
    mode:health         检查服务是否就绪
    mode:logs           跟踪运行日志
    mode:help           显示帮助

  项目任务
    mode:db:migrate     在当前环境执行数据库迁移

  常用操作
    bun run mode:start
    bun run mode:reload
    bun run mode:status -- --json

  说明
    reload 的构建与更新行为以当前运行方式为准。
──────────────────────────────────────────────────────────────────────
```

存在模式选择时单独加“运行方式”组，并明确选择是否自动启动；不存在则整组省略。依赖版本可在底部“运行环境”显示一行，不应占据主要说明区。说明必须准确描述该项目，不照搬样例的 restart/reload 行为。

## 色彩、宽度和共同渲染器

- TTY 默认彩色：标题加粗；成功绿（32）、警告黄（33）、失败红（31）、URL 和命令青（36）、标签/分隔线 dim（2）。每段结尾 reset（0）。状态同时带文字和符号，不能只靠颜色。
- 颜色优先级：--json 永远无色；NO_COLOR 存在时无色；FORCE_COLOR=0 无色；非零 FORCE_COLOR 强制彩色；否则按对应流 isTTY 且 TERM 不为 dumb 判断。
- 共享 `renderStatus`、`renderHelp`、`renderHealth`、`renderStep` 及 row/section/rule/paint 等小函数，查询状态与渲染分离。不要在每个 handler 中独立随意 console.log。
- 按终端显示列宽计算对齐：ANSI 序列宽度为 0，中文通常占 2 列。不要直接用带颜色字符串的 length/padEnd 对齐。可以采用已有终端宽度工具或明确的中文标签列；填充后再着色。
- 正常终端面板宽度参考 72–80 列，窄终端缩小并把长说明移到续行。不依赖复杂闭合表格边框，优先水平分隔线与两列布局。长路径/URL 保留完整可复制值，允许另起一行。
- start/reload 等过程按阶段输出，如 `[1/3] 构建镜像…`、`✓ 构建完成 · 8.2s`。成功后复用状态面板，失败输出错误摘要和下一步命令。原始构建日志允许保留，但不能成为唯一交付界面。logs 本身可以显示原始日志。

## 交付前必须验收

实现/修改管理器时，实际运行只读的 status/help，检查真实输出，而不是仅审查源码或声称“支持颜色”。通过渲染夹具覆盖停止和失败状态，不要为了界面测试停止真实开发服务。

1. 在 PTY、正常 TERM、未设置 NO_COLOR/FORCE_COLOR 时，确认默认出现语义颜色；NO_COLOR=1 下仍有完整面板和分组帮助。
2. 将 status/help 输出重定向到文件，确认仍是人类排版且无 ANSI，不能变成 JSON。FORCE_COLOR=1 时再检查 ANSI 确实存在且重置完整。
3. 检查 80 列和窄终端、中英文标签及长路径，信息分组清晰、两列对齐、命令不连成一坨。
4. status/health 的 --json stdout 能直接 JSON.parse，且 FORCE_COLOR=1 也不污染 JSON。
5. 成功/停止/异常状态不能仅用 true/false、ready 等内部值表示；每个帮助命令都有说明。
6. 交付说明附上实际 status/help 的代表性输出片段并说明颜色验证结果；禁止把本文静态样例冒充实际运行输出。

只更新本 skill 时，核对本文与入口及其他参考无冲突；上述运行验收由实际应用 skill 修改项目的任务执行。安装 skill 不会自动改写已有管理器代码。
